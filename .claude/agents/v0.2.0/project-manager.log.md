#### 风险清单

| 优先级 | 风险描述 | 影响 | 应对策略 |
|--------|---------|------|---------|
| 高 | **翻页状态管理复杂**：分页逻辑需要同时维护主列表和回收站的独立翻页状态（当前页码、每页大小），若与现有 TUI 状态模型耦合不当，容易引入页面跳转 Bug | 功能回归，用户体验下降 | TechLeader 需明确翻页状态的数据结构和切换边界条件；CodeReviewer 重点审查边界（首页/末页/空列表）处理 |
| 高 | **搜索功能与翻页的交互冲突**：搜索结果集发生变化时，当前页码可能超出新的结果范围，导致空白页或越界 | 功能错误（P0 级别） | 开发时明确约定：搜索条件变更时重置分页到第 1 页；Tester 需覆盖"搜索后翻页"和"翻页后再搜索"两个场景 |
| 中 | **时间格式改动的数据兼容性**：若已有回收站数据以旧格式（精确到分钟）存储，升级后读取时需确认显示行为一致 | 存量数据展示异常 | 开发者需检查时间戳存储格式（若存储的是 Unix timestamp，则仅需更改格式化输出，无兼容性问题）；若存储的是格式化字符串则需迁移方案 |
| 中 | **TUI 界面空间有限**：搜索框和翻页控件的 UI 布局需与现有界面元素协调，避免显示拥挤或信息截断 | 用户体验下降 | TechLeader 在架构设计阶段明确 UI 布局方案；CodeReviewer 关注终端宽度适配 |
| 低 | **搜索性能**：若回收站数据量极大（数千条），实时搜索可能有轻微延迟 | 用户感知卡顿 | 当前阶段采用简单字符串匹配即可；若有性能问题，Tester 需报告并由开发者评估是否需要优化 |

#### 可行性评估

三项功能均为 UI 层和业务逻辑层的增量改动，不涉及底层存储结构的破坏性变更（时间格式需确认存储方式）。技术实现路径清晰，可行性高。主要风险集中在翻页与搜索的状态联动，需 TechLeader 在阶段 3 前明确接口约定。

---

#### 总体建议

1. **模块划分建议**：建议 TechLeader 将三项功能划分为相互独立的模块——翻页模块、时间格式模块、搜索模块，降低并行开发的相互干扰风险。
2. **优先级建议**：翻页功能作为影响范围最广的核心变更，建议优先完成；搜索功能依赖翻页状态管理，建议串行排在翻页之后；时间格式修改最简单，可与翻页并行开发。
3. **测试重点**：Tester 需重点覆盖搜索+翻页联动场景，以及各功能的边界条件（空列表、单页、末页、搜索无结果等）。

## Backlog Manager TUI — Release Notes

### v0.2.0 (2026-03-12)

#### 新增功能

**1. 主列表与回收站翻页支持**

- 主列表（BacklogApp）和回收站（TrashScreen）在条目过多时支持分页浏览
- 每页默认显示 20 条记录，采用后端分页（LIMIT/OFFSET）确保大数据量下的性能
- 快捷键：`n` 下一页，`p` 上一页
- 状态栏显示当前页码和总页数（如 `Page 1/3 [N]ext [P]rev`）
- 切换过滤条件或搜索关键字时自动重置到第 1 页
- 从回收站恢复或永久删除条目后自动回退到合法页码

**2. 回收站搜索功能**

- 在回收站（TrashScreen）中支持按关键字搜索，匹配 title 和 description 字段
- 快捷键：`/`（在回收站界面按下）打开搜索弹窗
- 搜索关键字显示在底部提示栏（`Filter: "keyword"`），清除搜索显示 `Filter cleared`
- 搜索功能与翻页联动：搜索条件变更时自动重置页码

**3. repository 层分页 API**

- `repository.list()` 新增 `limit`、`offset` 参数，支持后端分页
- 新增 `repository.count()` 方法，返回满足当前过滤条件的条目总数（用于计算总页数）
- `repository.list_trash()` 新增 `keyword`、`limit`、`offset` 参数
- 新增 `repository.count_trash()` 方法，支持 keyword 过滤的回收站总数查询
- 向后兼容：所有新参数均有默认值，无参调用行为与 v0.1.x 完全一致

#### 改进项

**4. 回收站删除时间精确到秒**

- 回收站列表的"删除时间"列显示格式从 `YYYY-MM-DD HH:MM` 升级为 `YYYY-MM-DD HH:MM:SS`，方便用户区分同分钟内的多次操作

**5. 统计栏口径统一**

- 主界面底部状态栏的 `Total` 数值现与当前过滤条件（状态、分类、关键字）保持一致，消除了 `Total: 100 | Page 1/1` 等语义矛盾的展示问题

**6. 帮助文档完善**

- HelpScreen 导航部分新增翻页快捷键说明（`n` / `p`）
- HelpScreen 回收站部分新增回收站搜索快捷键说明（`/`）

#### 已知限制

- 翻页快捷键 `n`/`p` 在主列表和回收站界面均有效，但在编辑/添加等弹窗内无效（弹窗按 Esc 关闭后恢复）
- 当前搜索采用 SQL LIKE 匹配（`%keyword%`），对于极大数据量（数万条）的回收站可能有轻微延迟
- `count()` 与 `list()` / `count_trash()` 与 `list_trash()` 的 `datetime.now()` 在极端情况下存在微小时差（小于 1ms），不影响正常使用

### v0.2.0 (2026-03-12)

#### 新增功能

**1. 主列表与回收站翻页支持**

- 主列表（BacklogApp）和回收站（TrashScreen）在条目过多时支持分页浏览
- 每页默认显示 20 条记录，采用后端分页（LIMIT/OFFSET）确保大数据量下的性能
- 快捷键：`n` 下一页，`p` 上一页
- 状态栏显示当前页码和总页数（如 `Page 1/3 [N]ext [P]rev`）
- 切换过滤条件或搜索关键字时自动重置到第 1 页
- 从回收站恢复或永久删除条目后自动回退到合法页码

**2. 回收站搜索功能**

- 在回收站（TrashScreen）中支持按关键字搜索，匹配 title 和 description 字段
- 快捷键：`/`（在回收站界面按下）打开搜索弹窗
- 搜索关键字显示在底部提示栏（`Filter: "keyword"`），清除搜索显示 `Filter cleared`
- 搜索功能与翻页联动：搜索条件变更时自动重置页码

**3. repository 层分页 API**

- `repository.list()` 新增 `limit`、`offset` 参数，支持后端分页
- 新增 `repository.count()` 方法，返回满足当前过滤条件的条目总数（用于计算总页数）
- `repository.list_trash()` 新增 `keyword`、`limit`、`offset` 参数
- 新增 `repository.count_trash()` 方法，支持 keyword 过滤的回收站总数查询
- 向后兼容：所有新参数均有默认值，无参调用行为与 v0.1.x 完全一致

#### 改进项

**4. 回收站删除时间精确到秒**

- 回收站列表的"删除时间"列显示格式从 `YYYY-MM-DD HH:MM` 升级为 `YYYY-MM-DD HH:MM:SS`，方便用户区分同分钟内的多次操作

**5. 统计栏口径统一**

- 主界面底部状态栏的 `Total` 数值现与当前过滤条件（状态、分类、关键字）保持一致，消除了 `Total: 100 | Page 1/1` 等语义矛盾的展示问题

**6. 帮助文档完善**

- HelpScreen 导航部分新增翻页快捷键说明（`n` / `p`）
- HelpScreen 回收站部分新增回收站搜索快捷键说明（`/`）

#### 已知限制

- 翻页快捷键 `n`/`p` 在主列表和回收站界面均有效，但在编辑/添加等弹窗内无效（弹窗按 Esc 关闭后恢复）
- 当前搜索采用 SQL LIKE 匹配（`%keyword%`），对于极大数据量（数万条）的回收站可能有轻微延迟
- `count()` 与 `list()` / `count_trash()` 与 `list_trash()` 的 `datetime.now()` 在极端情况下存在微小时差（小于 1ms），不影响正常使用
